The Problem

Autonomous vision fails quietly.

A model saying "detected: object" isn't the same as the object actually being there. Most demos stop at detection. QUARRY starts from what happens after — because that's where trust in a real system actually gets built.

The Solution

Three roles, one verification loop.

The mission is split by what each participant is actually good at — a robot that measures instead of guesses, other robots that just watch, and people who make the final call.

INNER UGV
Drives to all 8 objects in strict numeric order. Heading derived from measured position, never a guessed yaw. Cross-checks OSNet's match against an independent OCR read of the object's printed number.
OUTER UGVs
Anyone else's real hardware, their own space. Share live position, raise an immediate alert the moment their own vision spots an unregistered person nearby. No voting gate — speed over consensus.
SPECTATORS
Watch the real camera feed and the Cyberwave twin together. Confirm or dispute: does what the robot actually captured match what the twin says lives there?

How It's Built

Every layer, named.

No unnamed magic — each piece of the stack is a specific, swappable technology, chosen for what this hardware can and can't do.

Robot
Waveshare UGV Beast — Pi 4B + ESP32, vision-only, no lidar
Platform
Cyberwave SDK + edge-core — pairing, MQTT telemetry, shared digital twin
Detection
YOLOE-26 (ultralytics) — real-time open-vocabulary object detection
Re-ID
OSNet (torchreid, osnet_x0_25) — appearance-based re-matching, persisted gallery
Identity check
Tesseract (pytesseract) — independent OCR read of printed marker numbers
Navigation
Motion-derived heading — closed-loop, measured, never a guessed yaw
Safety
CollisionGuard + driver watchdog — two independent layers
Backend
FastAPI + WebSocket — multi-site Hub, inner/outer roles, voting, alerts
