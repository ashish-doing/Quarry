The Real Problem, Underneath the Mission

ONE MODEL'S GUESS
ISN'T A VERDICT.

Underneath the recon framing is a real, named ML problem: human-in-the-loop verification to reduce false positives in autonomous vision — the same architecture behind citizen-science camera-trap labeling and content-moderation triage. Every confirmed or disputed vote is a human-verified label, feeding a real re-identification fine-tuning pipeline that refuses to run on insufficient data rather than reporting misleading numbers.

The Loop

FOUR STEPS.
EVERY OBJECT.

The inner UGV runs this loop for each of the 8 objects, in strict numeric order — no step skipped, no shortcut taken.

01

Capture

The inner UGV drives to the next AprilTag waypoint and waits for a properly-framed shot — not a premature snap the instant something's glimpsed.

Framing gate
02

Identify

YOLOE-26 detects the object; OSNet re-identification matches it against the registered gallery; Tesseract OCR reads its printed number as a second signal.

YOLOE-26 + OSNet + OCR
03

Compare

The captured identity is checked against what the Cyberwave twin claims lives at that waypoint, and raised as a candidate — not yet confirmed.

Twin cross-check
04

Verify

Remote spectators watching the real feed and the twin vote Confirm or Dispute. Net-positive consensus locks it into the confirmed_objects map.

Not Just Claimed — Verified

SAFETY YOU CAN
ACTUALLY TEST.

Every safety system here was physically tested, not just implemented. This is the one axis of this build with zero hand-waving.

Command-Loss Watchdog

✓ VERIFIED

If the link to the companion machine drops, the Pi's own driver-level watchdog stops the robot — independently, with zero dependency on the Hub or the network being otherwise reachable.

Verified by killing the control process mid-drive and timing the stop: 0.5s auto-stop, confirmed live.

CollisionGuard

✓ VERIFIED

An independent proximity emergency-stop using detection bbox-area as a distance proxy. This is explicitly not depth sensing — this hardware has no lidar or depth camera, and the page won't imply otherwise.

Two independent layers, no shared state — a software fault in one can't disable the other. Runs in both the inner UGV's agent and every outer UGV's relay process.
Co-op, Not Competitive

ONE MISSION.
THREE WAYS TO JOIN.

There's no team-vs-team framing here. Every real UGV — inner or outer — is physically in its own real space, but they all join the same shared Cyberwave twin environment, so every robot's position genuinely does appear together, even though nobody's hardware ever shares a room.

🎯 Inner UGV

The one robot running the actual mission. Autonomously surveys the 8 numbered objects in strict sequential order, drives itself between AprilTag waypoints, and is the only site whose candidates spectators vote on against the twin.

👁️ Outer UGV

Anyone else's real hardware, in their own physical space. Patrols independently, shares live position with the inner UGV through the Hub, and fires an immediate alert if its own vision spots an unregistered person nearby.

🗳️ Spectator

No hardware needed. Watches the inner UGV's real camera feed alongside the Cyberwave twin view and votes Confirm or Dispute on each captured object's identity — nothing counts as ground truth until people say so.
